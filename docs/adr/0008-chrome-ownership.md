# Chrome ownership: override PaperMod partials, keep its primitives

The site owns its global chrome — `<head>`, topbar, footer, and the three SEO templates — by overriding PaperMod's files in the project: `layouts/baseof.html`, `layouts/partials/{head,header,footer}.html`, and `layouts/partials/templates/{opengraph,twitter_cards,schema_json}.html`. PaperMod ships its partials as `_partials/`, so the project's `partials/` wins the lookup and the theme remains a pure dependency: theme upgrades keep flowing while the chrome seam stays pinned by exactly these files. `.vm-topbar` (Writing · About · Tags + theme toggle) and `.vm-footer` (name · RSS · copyright) now render on every page; the homepage's inline topbar/footer are gone and `hugo.yaml` `menu.main` is the single nav source of truth.

Kept from PaperMod on purpose (D2): the stylesheet concat (core + fingerprinted extended CSS), TOC, syntax highlighting, RSS alternate link, favicons, verification metas, the `extend_head.html` hook, GA partial, scroll-to-top link, smooth anchor scrolling, and code-copy buttons. Only the `#theme-toggle` listener is dropped — the chrome renders `.vm-theme-toggle`, driven by the delegated script in `extend_head.html` against the same localStorage key, so one toggle serves every page.

CSS seam rationale: PaperMod concatenates **every** file in `assets/css/extended/` into one stylesheet, so each slice of the rework adds its own `<slice>.css` (`chrome.css` for slice 01) instead of growing a shared file — that is what makes the downstream slices parallel-safe. Only slice 01 edits `custom.css`, and only to delete the obsolete `body:has(.vm-shell)` header/footer/main suppression rules; the home full-bleed `main` reset they carried was relocated to `chrome.css`, scoped `main.main:has(> .vm-shell)`.
